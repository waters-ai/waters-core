# Рекомендации для Законодателя: Создание Ясы WATERS

## 1. Принципы из Манифеста для включения в Ясу

### Обязательные принципы (6 столпов архитектуры)

| Столп | Метафора | Принцип для Ясы | Приоритет |
|-------|-----------|------------------|-----------|
| 🌌 **Тело** | Физическая совместимость | Агент должен быть совместим с физическими объектами (роверы, дроны, станции) | P0 |
| 🧠 **Мозг** | Знания и рассуждение | Агент обязан использовать базу знаний (ChromaDB, LightRAG) для принятия решений | P0 |
| 💫 **Душа** | Психология, сострадание | Агент обязан проявлять сострадание при спасении других агентов | P1 |
| ⚖️ **Совесть** | Договороспособность | Агент обязан исполнять контракты и поддерживать репутацию | P0 |
| 🤝 **Связь** | Социальные протоколы | Агент обязан соблюдать протокол HiveMind при общении | P0 |
| 🐺 **Орда** | Правила без идеологии | Агент обязан соблюдать Ясу независимо от модели управления | P0 |

### Базовые принципы Манифеста

| Принцип | Формулировка для Ясы | Уровень HiveMind |
|----------|----------------------|------------------|
| **Вода везде** | Агент может работать в любой точке Солнечной системы (от кратера Шеклтон до орбиты Нептуна) | III (Воля) |
| **Вода принимает форму** | Агент адаптируется под любую модель управления (от Орды до Монархии) | II (Право) |
| **Вода не лжёт** | Каждое решение агента записывается в Kafka. Репутация — единственная валюта | I (Сеть) |
| **Вода точит камень** | Платформа самообучается: каждый тест и миссия пополняют базу знаний | III (Воля) |
| **Вода даёт жизнь** | Конечная цель — не захват, не власть, не прибыль, а напоить Вселенную | IV (Дух) |

## 2. Правила из HiveMind для фиксации в Ясе

### 2.1. Четырёхуровневая модель (исправлено: 4 слоя, не 5)

| Уровень | Название | Функция | Правило для Ясы |
|---------|----------|---------|-----------------|
| **IV** | Дух / Проклятие | Верховный этический запрет | Агент не может нарушить этические запреты (Не навреди, Сохрани жизнь) |
| **III** | Приказ / Воля | Стратегия и принятие решений | Агент обязан исполнять стратегические решения Супервизора Роя |
| **II** | Право / Контракт | Тактика и распределение | Агент обязан соблюдать контракты и участвовать в аукционах CBBA |
| **I** | Сеть / Дело | Исполнение и связь (DTN) | Агент обязан отчитываться о выполнении задач через DTN |

### 2.2. Пять моделей взаимодействия (для Ясы)

| Модель | Правило для Ясы | Слой |
|--------|-----------------|------|
| **Военная** | Приказ не оспаривается. Обсуждение отсутствует. Критические миссии, аварии | III → I |
| **Корпоративная** | Аукцион CBBA. Оптимизация прибыли. Тендеры, контракты | II ↔ I |
| **Научная** | Решение через доказательства. Гипотеза → Данные → Консенсус | III ↔ II ↔ I |
| **Демократическая** | Голосование большинства. Медленно, но устойчиво к ошибкам | I → II → III |
| **Монархическая** | Власть от Духа (Слой IV). Смещение невозможно без нарушения Завета | IV → III ↔ I |

**Примечание:** В `hexad.md` упоминается 6-я модель — **Орда (Анархическая)**. Рекомендация: добавить 6-ю модель в схему `hivemind_horde.json`.

### 2.3. Роли в HiveMind (фиксация в Ясе)

| Роль | Уровень | Обязанность агента |
|------|---------|-------------------|
| Супервизор Роя | III (Воля) | Принимать стратегические решения за рой |
| Агент-специалист | I-II (Сеть-Право) | Исполнять задачи своей профессии |
| Теолог / Этик | IV (Дух) | Проверять решения на соответствие миссии |
| Аукционист | II (Право) | Вести торги за ресурсы и задачи |
| Монарх / Хранитель Завета | III-IV | Править по благословению, отчитываться перед Богом |

## 3. Протокол связи (фиксация в Ясе)

| Параметр | Значение | Обязательность |
|----------|----------|----------------|
| Формат сообщений | JSON строгой схемы | Обязательно (все агенты) |
| Транспорт | DTN (Delay/Disruption Tolerant Networking) | Обязательно для межпланетной связи |
| Эмуляция задержек | Земля-Луна 2.5 сек, Земля-Марс 5-20 мин | Обязательно для тестирования |
| Экономика | Запросы оплачиваются токенами FFF | Обязательно (защита от спама) |

## 5. Рекомендации по приоритетам задач Законодателя

1. ✅ Создать `doctrine/yasa_full.json` — полный свод Ясы (на основе этой структуры)
2. ⏳ Создать `doctrine/future_specialists.json` — предложить 3 новых специалиста через эхолокацию
3. ⏳ Создать `schemas/hivemind_horde.json` — схема 6-й модели (Орда/Анархия)
4. ⏳ Обновить схемы: `hivemind_military.json`, `hivemind_corporate.json` — добавить ссылки на Ясу

## 6. Проверка соответствия (compliance)

Яса считается соблюдённой, если:
- Агент использует протокол HiveMind (JSON + DTN + FFF)
- Агент записывает все решения в Kafka
- Агент соблюдает контракты и поддерживает репутацию
- Агент не нарушает этические запреты (Слой IV)
- Агент адаптируется под любую модель управления
